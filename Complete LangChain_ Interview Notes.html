Q1. What are Document Loaders?

  • What: a component that reads data from a source and converts it into Document objects
  • A Document has 2 fields: page_content (the text) and metadata (source, page number, etc.)
  • Why: data sits in PDFs, websites, CSVs, databases; the LLM needs plain text
  • Common loaders:
    • TextLoader: .txt files
    • PyPDFLoader: PDF, one Document per page
    • CSVLoader: one row becomes one Document
    • WebBaseLoader: web pages
    • DirectoryLoader: a whole folder
  • load() gives all docs at once; lazy_load() streams one by one (saves memory)
  • Mostly found in langchain_community.document_loaders
from langchain_community.document_loaders import PyPDFLoader
loader = PyPDFLoader("notes.pdf")
docs = loader.load()
print(docs[0].metadata)

Interview line: Loader = source in, list of Documents out. First step of RAG.

Q2. What are Text Splitters and their types?

  • What: breaks big Documents into small chunks
  • Why: context window is limited; small chunks embed and retrieve more accurately
  • chunk_size = max size of one chunk
  • chunk_overlap = text shared between neighbour chunks so meaning is not cut at the edge
  • Types:
    • CharacterTextSplitter: splits on one separator (default is a blank line), simple
    • RecursiveCharacterTextSplitter: tries blank line, then new line, then space, then single characters until the chunk fits. Best default
    • TokenTextSplitter: counts tokens, not characters
    • MarkdownHeaderTextSplitter / HTMLHeaderTextSplitter: split by headings, heading is kept in metadata
    • Code splitter: RecursiveCharacterTextSplitter.from_language(...)
    • SemanticChunker: splits where the meaning changes, uses embeddings (langchain_experimental)
  • Starting point: chunk_size 500 to 1000, overlap about 10 to 20 percent
from langchain_text_splitters import RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(
    chunk_size=800, chunk_overlap=100)
chunks = splitter.split_documents(docs)

Interview line: Too big = noisy. Too small = loses context. Tune by testing.

Q3. What is Embedding?

  • What: converting text into a list of numbers (a vector) that captures its meaning
  • Similar meaning = vectors close together, e.g. car and automobile
  • Models: OpenAIEmbeddings, HuggingFaceEmbeddings, GoogleGenerativeAIEmbeddings, OllamaEmbeddings
  • embed_query(text): one query
  • embed_documents(list): many chunks
  • Use the same model for storing chunks and for the user query
  • Size is fixed per model, e.g. text-embedding-3-small gives 1536 numbers by default
from langchain_openai import OpenAIEmbeddings
emb = OpenAIEmbeddings(model="text-embedding-3-small")
vec = emb.embed_query("What is RAG?")
print(len(vec))  # 1536

Interview line: Embeddings let us search by meaning, not by exact keywords.

Q4. What are Vectors?

  • Vector: an ordered list of numbers, e.g. [0.12, -0.8, 0.45, ...]
  • Each vector is a point in high dimensional space (hundreds or thousands of dimensions)
  • Closer points = more similar text
  • How closeness is measured:
    • Cosine similarity: angle between 2 vectors, range -1 to 1, most used
    • Dot product: fast, same as cosine when vectors are normalized
    • Euclidean (L2) distance: straight line distance, smaller = closer
  • More dimensions hold more detail but cost more storage and time

Interview line: Vector = coordinates of meaning. Search = find vectors nearest to the query vector.

Q5. What is a Vector Store?

  • What: a database that stores embeddings + original text + metadata and finds similar vectors fast
  • Uses ANN (approximate nearest neighbour) indexes like HNSW or IVF, so it does not compare with every vector
  • Examples:
    • FAISS: local library
    • Chroma: local, easy to start
    • Pinecone: managed cloud
    • Qdrant, Weaviate, Milvus
    • pgvector: inside Postgres
  • Main methods: from_documents(), add_documents(), similarity_search(query, k), similarity_search_with_score(), as_retriever()
  • Flow: Docs -> chunks -> embeddings -> store
from langchain_community.vectorstores import FAISS
db = FAISS.from_documents(chunks, emb)
res = db.similarity_search("What is RAG?", k=3)

Interview line: Vector store = storage + similarity search. Retriever sits on top.

Q6. What are Retrievers and how do they work?

  • What: an interface that takes a text query and returns a list of relevant Documents
  • It only retrieves; it does not have to store. Backend can be a vector store, BM25 keyword index, or an API
  • It is a Runnable: use .invoke(query) and chain it with |
  • How it works (vector retriever):
    • query -> embed the query
    • search the vector store
    • take top k nearest chunks
    • return them as Documents
  • search_type: similarity (default), mmr (relevance + diversity), similarity_score_threshold (minimum score)
  • Types:
    • MultiQueryRetriever: LLM writes several versions of the query
    • ContextualCompressionRetriever: trims irrelevant text
    • BM25Retriever: keyword based
    • EnsembleRetriever: hybrid, keyword + vector
    • ParentDocumentRetriever: search small chunks, return the big parent
    • SelfQueryRetriever: LLM builds metadata filters
retriever = db.as_retriever(
    search_type="mmr", search_kwargs={"k": 4})
docs = retriever.invoke("What is RAG?")

Interview line: Retriever = query in, relevant Documents out. Vector store is just one backend.

Q7. What is Context?

  • Context = everything the LLM sees in one call: system instructions, chat history, user question, retrieved chunks, tool results
  • In RAG: retrieved chunks pasted into the prompt are the context, the model answers from them
  • Context window: max tokens a model can handle in one call (input + output)
  • Too much context = costly, slow, details in the middle can be missed
  • Too little context = wrong or hallucinated answer
  • Context engineering: deciding what goes in, in what order, how much (top k, summarize old chat, trim)
  • In LangChain agents, runtime context (user id, db connection, settings) is passed separately and tools can read it
from langchain_core.prompts import ChatPromptTemplate
prompt = ChatPromptTemplate.from_template(
    "Answer using only this context:\n{context}\n\n"
    "Question: {question}")

Interview line: Context is what the model sees. Better context = better answer.

Q8. Explain Tools

  • What: functions a model can ask to run: web search, calculator, API call, database query, send email
  • The model does not run the tool. It returns a tool call (name + arguments), our code runs it and sends the result back
  • A tool has a name, a description (model reads this to choose) and an args schema
  • Create with the @tool decorator: docstring = description, type hints = schema
  • Attach to a model: llm.bind_tools([tool1, tool2])
  • Flow: question -> model returns tool call -> tool runs -> ToolMessage with result -> model writes final answer
from langchain.tools import tool

@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

Interview line: Tool = function + clear description + typed arguments. Bad description = wrong tool chosen.

Q9. What are Agents in LangChain?

  • What: an LLM that decides which tools to call and in what order, in a loop, until the task is done
  • Chain vs Agent: chain = fixed steps we write; agent = steps chosen by the model at run time
  • Loop (ReAct idea): think -> act (call tool) -> observe -> repeat -> final answer
  • Parts: model, tools, system prompt, memory (checkpointer)
  • LangChain 1.0: create_agent builds the agent, running on top of LangGraph
  • Middleware hooks customize the loop: summarize history, human approval, guardrails
  • Older style: AgentExecutor, create_react_agent (legacy)
  • Risks: endless loops, wrong tool, high cost. Set a step limit (recursion_limit), write clear tool descriptions
from langchain.agents import create_agent
agent = create_agent(
    model="openai:gpt-4o",
    tools=[add],
    system_prompt="You are a math helper.")
out = agent.invoke({"messages": [
    {"role": "user", "content": "What is 2 + 3?"}]})

Interview line: Agent = LLM + tools + loop. The model controls the flow.

Full pipeline, quick revision

  • Loader -> Splitter -> Embeddings -> Vector Store -> Retriever -> Prompt (context) -> LLM -> Answer
  • Loader: reads data into Documents
  • Splitter: makes chunks (size + overlap)
  • Embeddings: chunk to vector
  • Vector Store: stores vectors, similarity search
  • Retriever: query to top k Documents
  • Context: retrieved text placed in the prompt
  • Tools: functions the model can call
  • Agent: model + tools in a loop, retriever can be one of its tools

Interview line: RAG gives knowledge, tools give actions, agents give decisions.
